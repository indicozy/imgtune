imgtune GitHub

Send fewer image bytes.

How much image traffic can your pages stop sending? Most image tools compress the files you give them; imgtune measures what your live page actually sends against the space each image fills. It loads the page at six viewports, finds every image, and measures how many bytes a smaller size, a lower quality or a newer format would save. In a Next.js project it also gives the exact sizes and quality to change in your code.

npx imgtune scan https://your-site
Source on GitHub Package on npm Study results

How a scan works

  1. 1

    Chromium loads each page at six viewports: four phones, a 1440 px desktop at 2x, and a 1280 px desktop at 1x. The page is scrolled to the end, so lazy images load.

  2. 2

    Every image is recorded with the size it renders at and the file the browser fetched, including its srcset candidates.

  3. 3

    Exact savings come from the site's own smaller candidates. Each one is fetched and measured, so the number is the real byte difference.

  4. 4

    Est. savings come from a local re-encode at another quality or format, or a resize of a plain img. Quality is judged with SSIMULACRA2 at a delta of 2 points. Estimates are never presented as measured.

  5. 5

    An image smaller than its slot is reported as sharpness growth, separately. It contributes no saving, and its growth is never netted against other images.

Pages whose robots.txt disallows them are skipped and recorded as such. Pages behind a bot wall are recorded as blocked and not retried. imgtune uses the default Chromium user agent and no stealth plugins.

Five commands

scan
Measure any live site with no access to its source.
npx imgtune scan https://your-site
audit
In a Next.js project, measure the running app and propose sizes and quality. Writes .imgtune/report.json.
npx imgtune audit
apply
Write the proposals into your source files. imgtune never commits; git stays yours.
npx imgtune apply
verify
Re-check the applied changes against the images the server now serves. Changes no files.
npx imgtune verify
restore
Undo the temporary instrumentation an interrupted run left in your source.
npx imgtune restore

When verify reports a usage as regressed, it prints the exact command to raise its quality: npx imgtune apply --raise <Component>=<N>, then verify again. Run npx imgtune --help for every option.

What the study found

We scanned six production sites and eight open-source apps with the same tool version, two pages each, six viewports each. The site list was fixed before the first scan. Sites are anonymous here. Savings are the share of all image bytes per page view, with the page fully scrolled, averaged over viewports and then over pages.

Current tool (v4). Exact is measured. Est. is a local estimate, and where an image could not be scored it is a floor.

Kill criterion: a pass needs at least 2 of 6 production sites above 15%.

Exact alone: 2 of 6, exactly at the bar. Exact plus estimates: 6 of 6.

The first run (v1) gave 2 of 6 on exact and 4 of 6 with estimates. A3 moved from 13% to 38% in v4 because its images sit on a custom domain at quality 100, which v1 could not score.

Limits. Six deciders is a signal, not proof, and the sample leans toward sites without bot walls. Estimates are local re-encodes scored against the original, not bytes a server sent. Where a loader could not be scored, the estimate is a floor; the page JSON counts those images as qualityNA.

In CI

The composite action at the root of the repository scans the pages of each pull request and posts the result as one comment, updated on each push. Set fail-over to fail the job when a page is above a budget.

Each Vercel preview is a deployment_status event. This workflow scans the preview's URL and comments on the open pull request of the deployed commit.

name: imgtune preview
on:
  deployment_status:

permissions:
  contents: read
  pull-requests: write
  deployments: read

jobs:
  scan:
    if: github.event.deployment_status.state == 'success'
    runs-on: ubuntu-latest
    steps:
      - uses: indicozy/imgtune@main
        with:
          urls: ${{ github.event.deployment_status.environment_url }}
          fail-over: "5"

Two more examples, one for a local next start on the runner, are in docs/ci.md.

For coding agents

skills/imgtune/SKILL.md teaches Claude Code, and any tool that reads SKILL.md skills, to run scan, audit, apply and verify safely. It states the same rules as this page: exact and est. are reported separately, and nothing is committed.

Copy the skills/imgtune folder into your agent's skills directory. Read it on GitHub.
